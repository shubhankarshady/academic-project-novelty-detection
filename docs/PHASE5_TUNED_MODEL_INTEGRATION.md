# Phase 5.5: Tuned Hybrid Model Integration and Verification

## 1. Executive Summary

In Phase 5.5 of the Academic Project Novelty Detection platform, we have integrated the calibrated **Tuned Hybrid Model ($\alpha = 0.60$)** into both the FastAPI backend and the React frontend dashboard. The system now supports three operational scoring modes:
1. **TF-IDF Baseline (`tfidf`)**: Production baseline linear Ridge model over 8-section lexical n-grams (active default).
2. **Hybrid Baseline (`hybrid`)**: Convex combination baseline ($\alpha = 0.50$; 50% lexical TF-IDF, 50% dense semantic embeddings).
3. **Tuned Hybrid (`tuned_hybrid`)**: Empirically calibrated configuration ($\alpha = 0.60$; 60% lexical TF-IDF, 40% dense semantic embeddings with frozen candidate constrained section weights).

All tuned parameters are loaded dynamically from `models/phase5_tuned_hybrid_config.json`. No duplicate weights or hardcoded constants exist across the backend codebase, preserving zero-leakage research boundaries.

## 2. Model Architecture and Scoring Formulas

### 2.1 Multi-Section Similarity Extraction

Given a candidate proposal $C$ and historical corpus project $H$, similarity scores $s_k(C, H) \in [0.0, 1.0]$ are evaluated across the 8 standard academic proposal sections:
1. `title`
2. `abstract`
3. `problem_statement`
4. `objectives`
5. `proposed_methodology`
6. `dataset`
7. `algorithm_model`
8. `technology_tools`

For each section $k$:
- **Lexical Similarity ($s_k^{\text{lex}}$)**: Cosine similarity computed over sublinear TF-IDF vector spaces ($n$-gram range $(1, 2)$, English stop-words removed).
- **Semantic Similarity ($s_k^{\text{sem}}$)**: Cosine similarity of dense embeddings generated by `sentence-transformers/all-MiniLM-L6-v2` (384-dimensional normalized vector space, clamped to $[0.0, 1.0]$).

### 2.2 Mathematical Scoring Modes

$$\begin{aligned}
\text{TF-IDF Baseline:} \quad & s_k(C, H) = s_k^{\text{lex}}(C, H) \\
& \hat{y}_{\text{raw}} = \sum_{k=1}^8 w_k^{\text{ridge}} s_k(C, H) + b^{\text{ridge}} \\
& \hat{y} = \min(\max(\hat{y}_{\text{raw}}, 0.0), 4.0) \\[1em]
\text{Hybrid Baseline (\alpha=0.50):} \quad & s_k^{\text{hyb}}(C, H) = 0.50 \cdot s_k^{\text{lex}}(C, H) + 0.50 \cdot s_k^{\text{sem}}(C, H) \\
& \hat{y}_{\text{raw}} = \sum_{k=1}^8 w_k^{\text{cand}} s_k^{\text{hyb}}(C, H) \\
& \hat{y} = \min(\max(\hat{y}_{\text{raw}}, 0.0), 4.0) \\[1em]
\text{Tuned Hybrid (\alpha=0.60):} \quad & s_k^{\text{tuned}}(C, H) = 0.60 \cdot s_k^{\text{lex}}(C, H) + 0.40 \cdot s_k^{\text{sem}}(C, H) \\
& \hat{y}_{\text{raw}} = \sum_{k=1}^8 w_k^{\text{cand}} s_k^{\text{tuned}}(C, H) \\
& \hat{y} = \min(\max(\hat{y}_{\text{raw}}, 0.0), 4.0)
\end{aligned}$$

Where the active section weights $w^{\text{cand}}$ satisfy:
- $w_k^{\text{cand}} \ge 0 \quad \forall k$
- $\sum_{k=1}^8 w_k^{\text{cand}} = 4.0$
- $b = 0.0$

### 2.4 Novelty Percentage & Assessment Tier Formula

$$\text{Overall Novelty Score} = \left(1 - \frac{\max_{H \in \mathcal{D}} \hat{y}(C, H)}{4.0}\right) \times 100\%$$

| Predicted Max Similarity ($\hat{y}$) | Novelty Score Range | Assessment Tier | Recommended Action |
|:---:|:---:|:---:|---|
| $\ge 3.00$ | $0.0\% - 25.0\%$ | Low Novelty (High Similarity / Near-Duplicate) | Faculty Panel In-Depth Review |
| $2.00 - 2.99$ | $25.1\% - 50.0\%$ | Moderate-to-Low Novelty (Substantial Overlap) | Scope Refinement Required |
| $1.00 - 1.99$ | $50.1\% - 75.0\%$ | Moderate Novelty (Partial Overlap) | Viable with Highlighted Novel Contributions |
| $< 1.00$ | $75.1\% - 100.0\%$ | High / Exceptional Novelty | Strongly Original Research Initiative |

## 3. Backend Integration Architecture

### 3.1 Service Layer (`src/api/service.py`)

`NoveltyService` is a singleton service managing model lifecycles and inference explainers:
- **Default Scoring Mode**: Kept strictly as `"tfidf"` for production safety.
- **Dynamic Config Loading**: On startup, loads `models/phase5_tuned_hybrid_config.json` without modifying disk checkpoints.
- **Explainer Caching**: Maintains distinct cached instances for `_tfidf_explainer`, `_hybrid_explainer`, and `_tuned_explainer`, updating on demand when custom $\alpha$ parameters are requested.
- **Strict Self-Exclusion**: If a candidate proposal provides an explicit `project_id` matching a historical corpus record (e.g. `SYN-0001`), that historical project is excluded from candidate evaluation (`eligible_df = eligible_df[~exclude_mask]`). When evaluating an unassigned or new user submission (`project_id = None` or `"NEW_PROPOSAL"`), exact duplicates against the reference corpus are **NOT** excluded, ensuring near-duplicate alerts fire accurately.

### 3.2 API Schemas and Endpoints (`src/api/schemas.py`, `src/api/main.py`)

#### `GET /api/health`
Returns system status, historical vs submitted proposal counts, active mode, and supported modes:
```json
{
  "status": "healthy",
  "reference_corpus_size": 600,
  "submitted_proposals_count": 0,
  "model_loaded": true,
  "active_scoring_mode": "tfidf",
  "hybrid_alpha": 0.50,
  "available_scoring_modes": ["tfidf", "hybrid", "tuned_hybrid"],
  "tuned_hybrid_config": {
    "model_name": "Phase 5 Tuned Hybrid Fusion Model",
    "model_version": "phase5_tuned_hybrid_v1.0",
    "tuned_hyperparameters": { "alpha": 0.60 }
  },
  "message": "Active. Reference corpus contains 600 baseline historical projects. Database contains 0 user-submitted proposals. Active scoring mode: tfidf (alpha=0.50)."
}
```

#### `POST /api/score?mode={mode}&alpha={alpha}`
Evaluates a candidate proposal against all 600 baseline projects:
- **Query Parameter `mode`**: `'tfidf'`, `'hybrid'`, or `'tuned_hybrid'`.
- **Query Parameter `alpha`**: Optional numeric float override between $0.0$ and $1.0$.
- **Validation**: Enforces 8 required non-empty string sections with length constraints. Returns HTTP 422 Unprocessable Entity for invalid or insufficient inputs.

Example response snippet:
```json
{
  "candidate_proposal_title": "Deep Vision Architecture for Automated Agricultural Pathology Recognition",
  "candidate_project_id": "NEW_PROPOSAL",
  "scoring_mode": "tuned_hybrid",
  "hybrid_alpha": 0.60,
  "scoring_formula": "tuned_hybrid_similarity = 0.60 * tfidf_similarity + 0.40 * semantic_similarity; predicted_similarity = sum(w_i * hybrid_similarity_i) + intercept",
  "model_version": "phase5_tuned_hybrid_v1.0",
```

## 4. Frontend Integration

The user interface (`frontend/src/`) provides intuitive, explicit controls for model selection while preserving a clean, distraction-free SaaS layout:

1. **Model Architecture Selector (`ProposalForm.jsx`)**:
   - Exposed directly above the proposal input fields.
   - Segmented interactive pills allowing one-click selection between:
     - **TF-IDF Baseline**: 100% Lexical n-grams (Default).
     - **Hybrid Baseline ($\alpha=0.50$)**: 50% Lexical + 50% Dense Semantic.
     - **Tuned Hybrid ($\alpha=0.60$)**: 60% Lexical + 40% Dense Semantic (Calibrated).
2. **Evaluation Report Badges (`EvaluationReport.jsx`)**:
   - Displays active model badge, effective $\alpha$ weighting, exact scoring formula, and model release version.
   - Updates dynamically upon re-evaluation.
3. **Card-Level Scoring Badges (`SimilarProjectCard.jsx`)**:
   - Each matching historical project explicitly states which scoring pipeline and $\alpha$ factor produced its rank.
4. **Build Verification**:
   - Fully compiled production bundle via Vite (`dist/assets/index-*.js`, 0 compilation errors).

## 5. End-to-End Verification Protocol

Verification was conducted across seven scenario cohorts spanning all three scoring modes:

| Test Scenario | Test Input / Characteristic | TF-IDF Baseline | Hybrid Baseline | Tuned Hybrid | Verification Result |
|---|---|:---:|:---:|:---:|:---:|
| **1. Exact Copy (Unassigned ID)** | Verbatim duplicate of `SYN-0001` with `project_id = None` | Overlap Cluster Identified | $\hat{y} = 4.00$, Nov $0\%$ | $\hat{y} = 4.00$, Nov $0\%$ | **PASS**: Exact copy is NOT excluded |
| **1b. Exact Copy (Self-Excluded)** | Duplicate with explicit `project_id = 'SYN-0001'` | Excluded from results | Excluded from results | Excluded from results | **PASS**: Strictly excluded (599 evaluated) |
| **2. Strong Paraphrase** | Reordered syntax, novel vocabulary (`CASE_C`) | Lexical misses overlap | Surfaces disease context | Surfaces disease context | **PASS**: Semantic embeddings capture overlap |

## 6. Limitations of Preliminary Human Evaluation

> [!WARNING] Critical Scientific and Governance Caveats
> 1. **Single-Reviewer Source**: Ground truth calibration and held-out evaluation annotations were produced by a single reviewer (`Reviewer 1`). Inter-rater reliability (Cohen's / Fleiss's Kappa) and faculty panel consensus adjudication have **not** yet been conducted.
> 2. **Preliminary Heuristic Nature**: The tuned hybrid model improves held-out agreement ($84.44\%$ exact agreement vs $74.44\%$ baseline), but metrics reflect preliminary alignment with one reviewer's judgment rather than definitive scientific ground truth.
> 3. **Production Default Safeguard**: In accordance with governance protocols, the system default scoring mode remains `tfidf`. The `tuned_hybrid` mode must be explicitly selected by users or configured via environment variables (`NOVELTY_SCORING_MODE=tuned_hybrid`).
> 4. **Academic Originality vs Plagiarism**: Similarity scores indicate lexical and semantic overlap with the local reference repository; they do not establish academic plagiarism or guarantee academic acceptance.
